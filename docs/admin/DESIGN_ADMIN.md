# DESIGN_ADMIN

## Ключевые правки
- **Access until только для агента**: календарь выбора даты применяется к доступу агента в программу. Клиенты получают доступ по ссылкам от агента, без срока “access until” на клиента.
- **Расширенная статистика**: добавлена гибкая система метрик с возможностью наращивания под требования организаций (агентства, boards, unions, банки и др.).
- **Юридическая корректность просмотра документов**: доступ к документам легален только при соблюдении согласия, роли, цели обработки и соответствующей юрисдикции. Механизмы адаптированы под это.
- **Контроль доступа по реестрам организаций**: ИИ сверяет доступ агентов по спискам от агентств/boards/unions/банков, блокирует тех, кто не имеет права.

## Обзор админ-страницы
- **Навигация**: Dashboard, Agents, Requests, Logs, Settings.
- **Цветовая схема**: эталонная.
- **Принципы**: frictionless UX, авто-валидация, минимум ручных шагов, полная аудитируемость (логирование и changelog).
- **Масштабирование**: встроенный конструктор для сервисов/страниц, модульная архитектура для добавления новых приложений.
- **Возможность изменения структуры и функционала страницы админа с помощью конструктора** в будущем.

## Управление агентами
- **CRUD**: добавить, редактировать, удалить агента.
- **Access until (календарь)**: срок доступа агента к программе. Клиенты агента имеют доступ к странице, пока агент имеет доступ.
- **Membership number**: обязательное поле, включается в приглашение клиента для верификации источника.
- **Send link (расширено)**:
  - автоматическая генерация ссылки входа;
  - авто-отправка по SMS и email;
  - сохранение текущей ссылки в профиле агента;
  - регенерация новой при повреждении, с историей всех созданных ссылок;
  - ИИ анализирует причины повреждений ссылок и предотвращает их повтор.
- **Подтверждение контактов**: агент обязан подтвердить email и телефон (в увязке с 2FA).
- **Статистика заходов (расширяемая)**:
  - базовые метрики: логины/логауты, попытки входа, сбои 2FA, время сессий, активные страницы, отправленные приглашения, конверсия клиентов;
  - детализированные метрики: устройства/браузеры/локации, временные паттерны, аномалии, карта ошибок;
  - кастомные профили статистики: SLA, распределение статусов клиентов, скорость обработки документов.
- **Верификация банковских данных**: авто-сопоставление профиля агента с банковскими реквизитами.
- **Регистрация через landing page**: автосоздание агента, запуск верификации, подтверждения контактов и 2FA.
- **2FA**: обязательна для входа и чувствительных действий.

## Управление клиентами
- **Вложенность**: клиенты принадлежат агенту.
- **CRUD**: добавить, редактировать, удалить клиента.
- **View clients (модальное окно)**:
  - summary клиента: статус документов, результаты анализа ИИ, прогресс валидаций;
  - документы: просмотр строго по ролям и при согласии;
  - обучение ИИ: фиксация ошибок/корректировок;
  - автозаполнение: ИИ заполняет поля по документам, клиенты/агенты корректируют.

## Requests и Logs
- **Requests**: поток заявок клиентов для модерации, с ИИ-подсказками.
- **Logs**: аудит всех действий (агенты, клиенты, доступы, документы, ссылки, верификации).
- **Changelog**: история конфигурационных изменений.

## Роль ИИ админа и самообучение
- **Операционный мозг**: автоматизация CRUD, доступов, верификаций, рассылок, контроля по реестрам.
- **Аналитика документов**: выявление несоответствий, summary.
- **Безопасность**: управление 2FA, мониторинг Access until, минимизация доступа, детект аномалий.
- **Ссылки и приглашения**: генерация, отслеживание, анализ отказов.
- **Статистика**: отчёты, кастомизация метрик, поиск паттернов.
- **Самообучение**: на ошибках, корректировках, лучших практиках.

## Юридическая корректность доступа к документам
- **Основа доступа**: согласие клиента/правовая необходимость, ролевой доступ, цели обработки.
- **Ролевые политики**: админ/агент/ИИ имеют разные уровни.
- **Логирование и согласия**: запись согласий, времени доступа, цели, роли.
- **Модернизация при рисках**: если юрисдикция запрещает просмотр, UI показывает только метаданные.

## Конструктор и мульти-организации
- **Конструктор сервисов**: визуальный слой для создания новых сервисов, страниц, кнопок.
- **Мульти-организации**: поддержка агентств/boards/unions/банков, импорт реестров, верификация.
- **Модульность**: каждый сервис — самостоятельный модуль.
- **Будущее**: приложения для анализа документов, банковские сервисы, специфические статистики.

## Управление доступом
- Один супер админ управляет всеми правами.
- Супер админ назначает роли через интерфейс с чекбоксами.
- Доступы сгруппированы в шаблоны ролей и бандлы прав.
- Система проверяет совместимость прав, предупреждает о конфликтах и фиксирует изменения.

## Status реализации

### ✅ Уже внедрено
- Agents / Requests / Logs: базовые CRUD‑операции, хранение в AdminStore, логирование через addLog.
- Access until: поле у агента, календарь выбора даты (реализовано). У клиентов срока нет.
- Requests → Agents: логика перевода заявки в агента, включая Draft‑агентов.
- Логи: аудит всех действий, новые сверху, базовая пагинация и экспорт (CSV/JSON).
- UI‑валидация: уникальность boardMemberNumber при добавлении агента.

### ⚠️ Частично реализовано
- Send link (расширено): генерация и регенерация ссылки есть; авто‑отправка, история ссылок, анализ причин повреждений — отсутствуют.
- Логи: пагинация работает, но требует доработки (страницы по 10 записей). Экспорт CSV требует улучшения (BOM, кавычки).
- Requests: поток заявок реализован, но подсказки ИИ (approve/reject/revise) пока не внедрены.
- 2FA: заложено в описании программы, но в коде пока нет.
- Changelog: логи есть, но отдельного changelog для настроек/ролей нет.

### ❌ Пока отсутствует
- Расширенная статистика (метрики логинов, 2FA, активных страниц, SLA, аномалии).
- Подтверждение контактов (email/телефон + 2FA).
- Верификация банковских данных.
- Контроль доступа по реестрам организаций (boards/unions/банки).
- Юридическая корректность просмотра документов (согласия, цели обработки, юрисдикции).
- View clients (модальное окно: документы, автозаполнение, обучение ИИ).
- Конструктор сервисов и мульти‑организации.
- Управление доступом через супер админа (шаблоны ролей, бандлы прав, проверка конфликтов).
