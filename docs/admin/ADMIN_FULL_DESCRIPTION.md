# Ease Chequ Admin — Полное описание

## 🔹 Роли

- **Owner (владелец программы)** — управляет админкой, даёт доступ агентам, контролирует метрики и настройки.
- **Admin Staff (сотрудники)** — работают в админке.
  - _Super Admin_ — может изменять настройки.
  - _Viewer_ — только просмотр.
- **Agents (агенты)** — внешние пользователи, которым продаётся доступ к программе приквалификации клиентов. ⚠️ Не имеют доступа к админке.
- **Clients (клиенты)** — конечные пользователи, с которыми работают агенты. ⚠️ Отображаются на странице **Clients**, где видно к какому агенту прикреплён клиент. Здесь же проводится анализ, если клиент работает с несколькими агентами (multiple agents warning).

## 🔹 Страницы админки

### Dashboard (`/admin/dashboard`)

- Сводные метрики:
  - Active agents
  - Pending/Approved/Rejected requests
  - Deleted agents
  - Rejected agents
  - Multiple-agent clients
- Ссылки «View all» ведут в соответствующие разделы.
- Карточки отображают динамику и тренды.

---

### Agents (`/admin/agents`)

- Таблица всех агентов.
- Кнопка «Add Agent».
- Для каждого агента: имя, email, membership #, access until, invite link.
- Действия: Edit, Archive, Delete.
- При клике на агента → видно его клиентов.
- Workflow:
  - Delete → агент в Archive (type=deleted).
  - Restore → агент возвращается в Agents.

---

### Requests (`/admin/requests`)

⚠️ Requests = заявки от агентов (не клиентов!).

- Таблица заявок: имя агента, email, тип запроса, статус.
- Pending → кнопки Approve/Reject.
- Workflow:
  - Approve → агент переносится в Agents.
  - Reject → агент отправляется в Archive (type=rejected).

---

### Archive (`/admin/archive`)

- «Склад» для агентов, которые были удалены или отклонены.
- **Типы агентов в архиве:**
  - _Deleted_ — удалённые из Agents.
  - _Rejected_ — отклонённые из Requests.
- Содержимое: полный профиль агента, история действий, причина попадания.
- Действия: Restore → вернуть агенту доступ (перенос в Agents).
- Метрики Archive отображаются на Dashboard (раздельно для Deleted и Rejected).

---

### Clients (`/admin/clients`)

- Список всех клиентов, прикреплённых к агентам.
- Для каждого клиента: имя, контакты, прикреплённый агент.
- Анализ: multiple agents warning (если клиент работает с несколькими агентами).
- История показов (какая квартира/дом был показан клиенту).
- Используется для реализации **holdover‑логики**: фиксируется работа агента даже если сделка закрыта другим.

---

### Settings (`/admin/settings`)

- Настройки системы (тема, уведомления, параметры).
- Только Super Admin может изменять. Остальные роли — read‑only.

---

### Logs (`/admin/logs`)

- Аудит действий: список логов (дата, действие, пользователь).
- Автоматическая фиксация при действиях (addAgent, archive, approveRequest и т.д.).

## 🔹 Страница доступа для агентов

- Отдельная страница, куда агенты получают доступ после оплаты или на пробный период.
- Эта страница не является частью админки.
- Она станет **финальным продуктом** — CRM‑система для агентов.

---

## 🔹 Финальный продукт — CRM для агентов

- **Назначение:** рабочая страница агента, где он управляет своими клиентами.
- **Функционал:**
  - Просмотр списка клиентов.
  - Добавление новых клиентов.
  - Источники клиентов: Facebook Ads, Google Ads, Landing Page, другие интеграции.
  - Возможность выбора клиента и просмотра его данных.
  - Отправка запроса на анализ документов для приквалификации.
  - Предупреждение, если клиент работает с несколькими агентами.
  - История показов (holdover).
- **База данных:** рассчитана на большую нагрузку, фиксируются все агенты и их клиенты.
- **Архитектура:** CRM‑страница агентов будет связана с админкой, но это отдельный уровень доступа.

---

## 🔹 Стратегия разработки

- **Этап 1: Админка**
  - Управление доступами, заявками, архивом, метриками, клиентами.
  - Фундамент для контроля и масштабирования.
- **Этап 2: CRM для агентов**
  - Реализация финального продукта.
  - Подключение к админке через общую базу данных.

💡 **Рекомендация:** начинать с админки, чтобы задать структуру ролей, workflow и контроль доступа. CRM можно подключить позже как отдельный модуль.
