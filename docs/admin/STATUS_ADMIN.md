Страница админа
•	MVP (реализовано/в процессе) — то, что уже работает или в ближайшей доработке.
•	Расширение (будущее) — то, что зафиксировано в твоём старом описании и должно остаться в каноне, но реализуется позже.

📂 Каноническое описание админ страницы (объединённое)
1. Навигация и архитектура
•	Разделы: Dashboard, Agents, Requests, Logs, Archive, Settings, Access.
•	Layout: 
o	app/layout.tsx — корневой, глобальные провайдеры.
o	app/admin/layout.tsx — вложенный, содержит AdminProvider, Sidebar, Topbar.
•	Цветовая схема: эталонная (переменные --app-bg, --sidebar-bg, --topbar-bg, --card-border, --secondary-text).
•	Принципы: frictionless UX, авто валидация, минимум ручных шагов, полная аудитируемость (логи + changelog).
•	Масштабирование: модульная архитектура, возможность добавления сервисов/страниц.
________________________________________
2. Управление агентами
MVP:
•	CRUD: добавить, редактировать (AgentEditModal), удалить (AgentDeleteModal → архив).
•	Access until: календарь срока доступа (только для агента).
•	Membership number: обязательное поле.
•	Invite ссылка: 
o	Генерация при активации (Active).
o	Кнопки: Generate, Regenerate, Revoke.
o	Invite = одноразовый токен для первого входа (email+пароль+2FA).
o	После регистрации агент входит через портал, invite становится Used/Expired.
•	Архивирование: удалённые агенты → archivedAgents, можно восстановить.
•	Клиенты: список, привязка по agentId, detach.
Будущее:
•	Авто отправка invite по email/SMS.
•	Подтверждение контактов (email+телефон) + 2FA.
•	Статистика заходов: логины, сбои 2FA, устройства, локации, SLA отчёты.
•	Верификация банковских данных.
•	Регистрация через landing page.
________________________________________
3. Управление клиентами
MVP:
•	Клиенты принадлежат агенту.
•	Моки клиентов для теста.
Будущее:
•	CRUD клиентов.

•	2FA для клиентов при доступе к документам.
________________________________________
4. Requests
MVP:
•	Секция показывает только Pending.
•	Approve: 
o	Создаёт агента (Pending).
o	Переносит заявку в archivedRequests (Approved).
o	Логируется.
•	Reject: 
o	Переносит заявку в archivedRequests (Rejected).
o	Логируется.
•	Правило: Rejected нельзя одобрить напрямую, только через восстановление в Pending.
Будущее:
•	ИИ подсказки (approve/исправить/reject).
•	SLA метрики по заявкам.
________________________________________
5. Archive
MVP:
•	Deleted Agents: список + Restore.
•	Archived Requests: Approved и Rejected, можно восстановить в Pending.
________________________________________
6. Logs
MVP:
•	Лента событий: тип, сообщение, timestamp.
•	Пагинация: по 10 записей, кнопки Next/Previous.
•	CSV экспорт.
Будущее:
•	Расширенные changelog: история конфигураций, версионирование UI/ролей.
________________________________________
7. Access
MVP:
•	Панель управления ролями.
•	Роли: Super Admin, Admin, Viewer.
•	Viewer = только просмотр (UI disabled).
•	Смена ролей логируется.
Будущее:
•	Bundles прав.
•	Проверка совместимости ролей.
•	Все критические действия требуют 2FA.
________________________________________
