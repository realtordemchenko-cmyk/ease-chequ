# Страница админа

• **MVP (реализовано/в процессе)** — то, что уже работает или в ближайшей доработке.  
• **Расширение (будущее)** — то, что зафиксировано в каноне, но реализуется позже.  

---

## 📂 Каноническое описание админ страницы (объединённое)

### 1. Навигация и архитектура
- Разделы: **Dashboard, Agents, Requests, Logs, Archive, Settings, Access**.  
- Layout:  
  - `app/layout.tsx` — корневой, глобальные провайдеры.  
  - `app/admin/layout.tsx` — вложенный, содержит `AdminProvider`, `Sidebar`, `Topbar`.  
- Цветовая схема: эталонная (переменные `--app-bg`, `--sidebar-bg`, `--topbar-bg`, `--card-border`, `--secondary-text`).  
- Принципы: frictionless UX, авто‑валидация, минимум ручных шагов, полная аудитируемость (логи + changelog).  
- Масштабирование: модульная архитектура, возможность добавления сервисов/страниц.  

---

### 2. Управление агентами
**MVP:**
- CRUD: добавить, редактировать (`AgentEditModal`), удалить (`AgentDeleteModal` → архив).  
- Access until: календарь срока доступа.  
- Membership number: обязательное поле.  
- Invite ссылка:  
  - Генерация при активации (Active).  
  - Кнопки: Generate, Regenerate, Revoke.  
  - Invite = одноразовый токен для первого входа (email+пароль+2FA).  
  - После регистрации invite становится Used/Expired.  
- Архивирование: удалённые агенты → `archivedAgents`, можно восстановить.  
- Клиенты: список, привязка по `agentId`, detach.  

**Будущее:**
- Авто‑отправка invite по email/SMS.  
- Подтверждение контактов (email+телефон) + 2FA.  
- Статистика заходов: логины, сбои 2FA, устройства, локации, SLA отчёты.  
- Верификация банковских данных.  
- Регистрация через landing page.  

---

### 3. Управление клиентами
**MVP:**
- Клиенты принадлежат агенту.  
- Моки клиентов для теста.  

**Будущее:**
- CRUD клиентов.  
- Модальное окно просмотра: summary, документы (по ролям и согласиям), автозаполнение ИИ, обучение на корректировках.  
- 2FA для клиентов при доступе к документам.  

---

### 4. Requests
**MVP:**
- Секция показывает только Pending.  
- Approve:  
  - Создаёт агента (Pending).  
  - Переносит заявку в `archivedRequests` (Approved).  
  - Логируется.  
- Reject:  
  - Переносит заявку в `archivedRequests` (Rejected).  
  - Логируется.  
- Правило: Rejected нельзя одобрить напрямую, только через восстановление в Pending.  

**Будущее:**
- ИИ‑подсказки (approve/исправить/reject).  
- SLA‑метрики по заявкам.  

---

### 5. Archive
**MVP:**
- Централизованная страница `/admin/archive`.  
- Deleted Agents: список + Restore.  
- Archived Requests: Approved и Rejected, можно восстановить в Pending.  
- Поддержка query‑параметров: `?page=agents`, `?page=requests&type=approved|rejected`.  

---

### 6. Logs
**MVP:**
- Лента событий: тип, сообщение, timestamp.  
- Пагинация: по 10 записей, кнопки Next/Previous.  
- CSV экспорт.  

**Будущее:**
- Расширенные changelog: история конфигураций, версионирование UI/ролей.  

---

### 7. Access
**MVP:**
- Панель управления ролями.  
- Роли: Super Admin, Admin, Viewer.  
- Viewer = только просмотр (UI disabled).  
- Смена ролей логируется.  

**Будущее:**
- Bundles прав.  
- Проверка совместимости ролей.  
- Все критические действия требуют 2FA.  

---

### 8. Settings
**MVP:**
- Заглушка.  

**Будущее:**
- Банковские реквизиты агентов (`bankAccount`/`paymentMethodId`).  
- Счёт администратора.  
- Интеграция с платёжными шлюзами (Stripe/PayPal/банковский API).  
- Email‑сервис для отправки invite и уведомлений.  
- Webhooks для авто‑активации при оплате.  

---

### 9. Юридическая корректность
**Будущее:**
- Доступ к документам только при согласии клиента или правовой необходимости.  
- Ролевые политики: разные уровни видимости.  
- Логирование согласий, целей обработки.  
- При рисках: UI показывает только метаданные.  

---

### 10. Конструктор и мульти‑организации
**Будущее:**

- Поддержка агентств/boards/банков.

## 📌 Разделение на этапы

**MVP (сейчас):**
- Навигация (Dashboard, Agents, Requests, Logs, Archive, Settings, Access).  
- Agents CRUD + Access until + Membership number.  
- Invite ссылка (генерация, регенерация, отзыв).  
- Requests approve/reject → архив.  
- Archive (централизованный, Deleted Agents + Archived Requests).  
- Logs (пагинация, CSV).  
- Topbar, Sidebar.  
- Управление ролями (Super Admin/Admin/Viewer).  

**Расширение (будущее):**
- Авто‑отправка ссылок по email/SMS.  
- Подтверждение контактов, 2FA.  
- Расширенная статистика, SLA отчёты.  
- Верификация банковских данных.  
- Landing page регистрация.  
- Клиентские CRUD + модальные окна.  
- Конструктор сервисов, мульти‑организации.  
- Юридическая адаптация по юрисдикциям.  
- Интеграция с платёжными шлюзами.
