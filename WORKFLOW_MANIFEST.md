## 📌 Общие правила

1. Все ответы должны быть **полными и готовыми к использованию**.  
   - Для кода: всегда возвращать **цельный файл**, а не фрагменты.  
   - Для скриптов (PowerShell, Bash, SQL, Python и др.): давать **полный рабочий код**.  
   - Все комментарии внутри файлов — на английском.  
   - Общение со мной — на русском.  

2. Каждый шаг работы сопровождается:  
   - Объяснением, что делается и зачем.  
   - Проверкой, нет ли уже существующих файлов/функций, выполняющих ту же задачу.  
   - Подтверждением, что код не дублирует функционал.  

3. Все изменения должны быть **воспроизводимыми**:  
   - Указывать путь к файлу.  
   - Давать полный текст файла.  
   - Обновлять память о состоянии проекта.

## 🖥 Работа с файлами

- Для **каждого файла** команда открытия в PowerShell должна идти **непосредственно перед кодом этого файла**.  
- Формат выдачи:  
  1. Команда для открытия файла.  
  2. Полный код файла.  
  3. Пояснения, проверки, выводы.  
- Если несколько файлов:  
  - Команда для открытия файла → Первого файл → остальное.  
  - Команда для открытия второго файла → Код Второго файл → остальное.  
  - И так далее.  
- **Запрещено** объединять все команды открытия файлов в одном блоке.  

- При изменении файла:  
  - Давать полный обновлённый файл.  
  - Подчёркивать, что старый вариант заменяется.  

- После каждого значительного изменения (добавление ≥5 новых файлов) обновлять карту проекта:  
  ```powershell
  tree "D:\Projects\Ease Chequ" /F /A > "D:\Projects\Ease Chequ\project-structure.txt"
  ```
- Мы документируем файлы структуры программы. Это будет отдельный раздел, чтобы у нас всегда был эталон, описыващй какие файлы за что отвечают по категориям
Мы планируем 5 категорий файловой структуры:
- Layout‑файлы (каркас).
- Страницы (контейнеры).

- Документация (описание и changelog).
- Будущие модули (конструктор, мультиорганизации).

## 🔍 Проверка и аудит

- Перед добавлением нового кода проверять:  
  - Существуют ли уже функции с таким назначением.  
  - Есть ли дублирующие файлы.  
- При обнаружении дублирования:  
  - Предлагать архитектурное решение (рефакторинг, вынос в сервис, объединение).  
- Следить за тем, чтобы **не плодились повторяющиеся по функционалу файлы**.  
- Прогонять код в памяти, применяя известные компоненты программы, минимизировать ошибки на 99%.
